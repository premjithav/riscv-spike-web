Debug mode drives Spike's own interactive debugger (spike -d). A browser page cannot pause Spike while it waits for your next command, so each command re-runs the program from reset with your whole command history. Spike is deterministic, so the replay lands in the same state; that is also why Undo last can step backwards.

Enter (empty)
Execute one instruction and print it.
until pc 0 <addr|symbol>
Run silently until hart 0's PC equals the address. Symbol names from the ELF are translated for you.
untiln pc 0 <addr>
Same, printing every instruction on the way.
while reg 0 a0 0
Run while register a0 equals 0. until/while also take mem <addr> <value> and insn 0 <encoding>.
r [n] · rs [n]
Run n instructions, printing them (r) or silently (rs). Without n, runs to the end.
reg 0 [name] · freg 0 fa0
Show all integer registers, one register, or a floating-point register.
mem 0 <addr> · str 0 <addr>
Read a 64-bit word or a NUL-terminated string from memory (hex address or symbol).
pc 0 · insn 0 · priv 0
Current PC, the instruction at it, and the privilege mode.

Programs print through HTIF: Spike's front-end server catches tohost writes and proxies write() to this console. ISA tests print nothing on success; a failure reports *** FAILED *** (tohost = N), where N >> 1 is the failing test case. Benchmarks report tohost = 1337 when they take an unexpected trap; try mm on the rv64imac hart, which has no FPU.

This build was checked against native Spike with the riscv-tests suite. Uploaded ELFs must be bare-metal programs linked at 0x80000000 that exit through tohost; Linux binaries need a proxy kernel, which is not included.
